One-liner

A non-custodial payment preflight that resolves QIE's 0x and qie1 account representations and verifies a short-lived EIP-712 wallet-control proof before funds move.

Problem and differentiation

QIE's dual address representation creates a practical integration risk for wallets, exchanges, bridges, and payment apps: a valid-looking value may be the wrong representation for a destination field, while a copied address pair does not prove recipient control. SafeRoute combines deterministic QIE-specific address resolution and a constrained portable proof in one preflight flow. It is not another wallet, checkout clone, identity score, or custody layer.

QIE integration

  • QIE EVM 0x ↔ qie1 bech32 conversion and validation.
  • QIE Testnet chain ID 1983 wallet switching and EIP-712 domain.
  • Public QIE genesis account used as a reproducible test vector.
  • Optional Solidity registry for proof-hash anchoring and revocation.

MVP evidence

Working responsive React/TypeScript app; local dual-address resolution verified against QIE's public chain registry, Cosmos API and mainnet explorer; wallet-signed Payment Intent creation; offline JSON/QR verification; malformed-input, expiry and context-substitution handling; 12 passing SDK tests and 5 passing contract tests; successful lint and production build; zero vulnerabilities in the production dependency tree.

Deployment disclosure

The front end is publicly hosted, but no registry contract has been deployed to QIE Testnet or QIE Mainnet, and no transaction has been broadcast. The optional registry source is included and compiles. Mainnet deployment requires separate owner authorization and security review.
